# Demon Killer M39 | One DK Architect, all regions

Status: integrated owner-requested build. No release tag until accepted.

## Underlying architecture

The active temple and outdoor pages now load **the same**:
- \`dk-architect-catalog-m39.js\`: original approved 32px sprites, tiles, props, imported-art metadata and direction/footprint definitions.
- \`dk-architect-core-m39.js\`: one construction tool mode, category, selected asset and cardinal rotation controller.
- \`dk-architect-ui-m39.js\` and matching CSS: Prison Architect-inspired **bottom construction categories** that open **searchable flyout menus above the bar**. Real prototype thumbnails and commands, with unavailable tools clearly disabled.

The temple and outdoors use small region adapters for their different saved map formats. Those adapters do **not** define competing tool lists or separate sprite catalogs.

## Delivered behavior

- **Inside and outside:** F8 and ARCHITECT button; identical construction categories and asset catalog; selection, placement, rotation, moving, copying/duplicating, removal, walls, floor materials, doors, spawn marker, save/export and undo/redo appropriate to each map.
- **Temple:** Existing 16×16 scene, original sprites, ritual and left-interact / right-move gameplay stay intact. Architect object movement gains the same **drag** gesture and green/red placement preview as outdoors; original undo history remains authoritative.
- **Courtyard and village:** Edit the **live game map** without an iframe; pan/zoom, move an entire physical building including wall/floor layers and door, edit real exterior doors, paint ground and approved floor/wall art, build cardinal walls with drag brush/straight runs/room outlines, place approved DK sprites and decorative objects, rotate/move/remove/duplicate/copy/paste them, move well/stall fixtures, set the spawn marker, and undo/redo map edits.
- **World consistency:** Browser and Node server share geometry, asset validation and collision. Props with collision block living movement but remain passable for ghosts. Stable IDs preserve house deeds, storage positions and vendor stock after moving buildings. The temple, paths, gates and the future Lilith willow location remain unchanged by this build.
- **Browser Pages:** Layout drafts persist separately from characters in localStorage and **Export JSON** produces a map-only package to send for integration. No imaginary server and no local install required.

## Scope and limitations

- The default map layout is preserved until the owner edits and exports it. Lilith's camera cutscene is not changed.
- Newly staged actor visuals are props, **not instantly simulated NPCs**. The real NPC economy and schedules remain part of the separate persistent server project.
- Outdoor objects are placed with the existing original 0x72 and approved DK sprites. They do not create playable new building interiors; interiors remain a later connected-world milestone.
