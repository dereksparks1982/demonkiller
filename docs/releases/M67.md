# M67 | Code-only replacement-world foundation

Game: **0.2.65**. Server: **2.31.11**.

## Scope

Retire the existing temple, courtyard and village layouts **as the design basis for the new world**. No new scenery, scene artwork, terrain map, story changes or town prefab is introduced.

The new `world_grid` save record is blank and independent of legacy named areas. Its logical bounds are 4096 by 4096 32px tiles. Streaming Cells are 128 by 128 tiles; detailed sectors are 16 by 16 tiles. Coordinate helpers work over the full world without allocating 16,777,216 tile arrays.

## Code delivered

- Deterministic global tile → sector/cell addressing; cardinal-only stepping, edge checks and four-neighbor cell lookup.
- Cross-cell, cross-sector building draft footprints with stable identifiers, optional owner references and no implicit material creation.
- Rejected overlaps, malformed records, out-of-bounds coordinates and invalid layouts.
- Persistent, non-destructive save migration, plus strict validation on later writes.
- Read-only `GET /api/v1/world/grid` diagnostics, optionally with `?x=128&y=128`; no client-side placement commands.

## Transition boundary

Older M66 server systems still depend on the named temple/courtyard/village areas. Deleting those live areas now would corrupt their NPC, business and save dependencies. The replacement world remains entirely unpopulated, and **no legacy scene is copied into it**. Existing browser play is a legacy compatibility view until a future migration build can remove these dependencies safely.

## Verification

Core module evaluated with boundary-crossing, edge, draft, overlap rollback and migration checks. `tests/world-grid-m67.cjs` is registered in the server regression runner. Full Node integration suite and browser testing have not been run in this environment.
