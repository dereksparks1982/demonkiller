# Demon Killer M28 - Item lifecycle and accessible containers

Released as DK Server 2.8.0. Builds on M27 without changing world movement, persistence schema, or the C/P/I gameplay shortcuts.

## Server
- Supports full-stack moves by a persistent item serial using `move_stack`; ordinary `move_item` retains its earlier 20-unit per-request limit.
- Adds `equip_item` and `unequip_item` with server-owned equipment-slot validation and persistent serials.
- Extends `split_stack` and `combine_stacks` to physically accessible bank, chest and owned-house storage. Remote/inaccessible containers are not enumerable or mutable.
- Expands the existing `GET /api/v1/inventory` snapshot with accessible container capacity, usage, and serial-addressed contents. The inventory endpoint does not grant access to arbitrary world containers.
- Preserves entity-registry invariants, NPC/world state, versioned world saves, and the server's single-writer action queue.

## Client
- Temple and outdoors use the same server-owned item serials for backpack and equipment interaction.
- Double-click equipped items to unequip; drag them back into the bag; drag backpack items onto appropriate equipment slots; split stacks with Shift + double-click, merge by dragging.
- Outdoors can drop an entire backpack stack by dragging onto the playable world canvas. The server validates the drop location.
- No additional gameplay shortcut buttons. C opens Cult in temple, P opens the paper doll, I opens the backpack.

## Validation
- Added `tests/item-lifecycle-m28.cjs` covering item conservation, full stacks, equipment identities, remote access denial, owned-house/chest transfers, full-pack refusal, restart survival, and simultaneous stale actions.
- Ran focused pure-logic serial and access checks via an isolated harness; full Node regression suite remains to be confirmed by CI or a local `npm test --prefix server` run.
