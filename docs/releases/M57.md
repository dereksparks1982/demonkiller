# M57 | Restore Lilith's Approved First-Courtyard Cinematic

## Root cause

The current outdoor client had lost the original M40 camera/prayer/transition engine. It substituted a six-second, stationary procedural tree and a hand-drawn living-world Lilith. The local server also failed to allowlist the missing M40 JavaScript and CSS. It marked first visits finished before the scene completed, while networking could consume the cinematic timeline before the first rendered frame. Retired colored-block pixel fallbacks still flashed in player and Lilith rendering paths.

## Fixed

- Restore the **original, previously approved** M40 `dk-lilith-cinematic-m40.js` and stylesheet and serve them from the loopback DK Server. Nothing new is generated. The source is the actual 12-panel `assets/art/characters/crystal-woman/transformations/approved-willow-transformations-reference.png` already in the repository.
- Leaving the temple into the courtyard locks input and hides the player. Pan to Lilith at the southern path, track her as she walks north to the central circle, display **three prayer passages**, then render the **six original transition frames** for that state. Ghost: red hair and green dress becoming a healthy golden willow. Living: red hair and red dress becoming the sickly black willow.
- Hold the transformed tree; pan back to the character; only then restore the player sprite and controls. Subsequent visits show the completed approved willow, not an improvised coat-hanger tree.
- The saved first-exit branch remains stable even if the character form later changes. Neither moving nor selecting DK Architect can interrupt the scene.
- M57 completion markers supersede old falsely completed visits. Mark a cinematic complete only after its **full** return-pan phase. Restart its timer once initial server data has loaded, so a slow server does not consume the cutscene before its first frame. The scene does **not** reset the character, world, buildings, or saves.
- Temple and outdoors player drawings and outdoor paper-doll portraits display only approved sprites, without the legacy block-art fallback showing underneath or briefly during image load. The temple's Lilith and sacrificial body likewise no longer use old block-art substitutes.
- Cache-bust the modified temple/outdoor scripts and restored Lilith modules, leaving all previously built world/economy systems intact.

The Node regression script includes both. These are source/timeline/server-contract tests, **not** a claim that a browser was visually tested.
