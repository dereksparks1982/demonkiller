# Demon Killer M35 | DK Architect Interior Draft Foundations

**DK Server v2.15.0**

## What is built
- Durable `world.living.interior_drafts` store for draft interiors tied to existing **variable-sized building Streaming Cells**. This extends the actual M33/M34 Streaming Cells, not the fixed 16×16 terrain sector grid.
- Existing temple, courtyard and village sizes stay unchanged. Each building may have an independently sized interior blueprint from 4×4 up to 64 in either dimension, with a maximum area of 2,048 tiles per draft. Actual building exteriors do not determine interior dimensions.
- Each draft has a title, own revision, entry tile, seven floor/wall/art tile layers, and a validated list of placed objects. All drafting records live inside the canonical world save and inherit its atomic writes and backup recovery.
- The entry tile is reserved. Tile paint cannot seal it with a wall. Objects are validated for allowed types, unique IDs, cardinal rotations, and bounds.
- Draft commands: `create_draft`, `paint_tiles` (up to 32 individual tile edits), `place_object`, `remove_object`, and `rename_draft`.
- Optimistic draft revision checks return a conflict when an older editor tries to overwrite a newer draft. Invalid or partial edit requests never alter the saved world; room count and total tile budgets are bounded.
- Legacy M34 and earlier world saves migrate to the new draft store at startup. Deleting the player does not delete the drafted world buildings.

## DK Architect workspace
The separate local-server page `/dk-architect-interiors-m35.html` supports building selection, choosing the room's dimensions, creating/reloading a draft, painting tiles, rectangle painting, and placing/removing original-world object types. The mouse wheel rotates a selected object preview; right-mouse drag pans the editor. Changes are saved through the local DK Server, not directly to the filesystem.

The editor is deliberately **not** added as a button to the playable scene. It operates on draft blueprints and does not move or reinitialize the character.

## Server API
- `GET /api/v1/architect/interiors`: list real building cells and draft revision summaries.
- `GET /api/v1/architect/interiors/draft?cell_id=...`: fetch the saved draft and its tile layers.
- `POST /api/v1/architect/interiors/draft`: edit a draft using `X-DK-Architect: draft` and `expected_revision` in the body; uses the server's single-writer save queue.
- The same DK Architect operations are exposed through `window.DemonKillerServer` when visiting the local game host. The public static preview has no pretend world-writing API.

## Important limits
**Drafts do not create playable interiors.** Every existing building remains non-enterable, even if a draft exists. No door teleportation, interior NPC spawning, movement changes, automatic character transitions, or counterfeit room maps were added.

This build provides the editable, durable foundation. Later builds must explicitly approve real interior portals, collision, per-room NPC/item lifecycles, and publishing before the player can go inside.

## Testing and verification
- `tests/interior-drafts-m35.cjs`: draft creation, independently sized rooms, tile paint, object placement/removal, stale-write rejection, migration, save integrity, character deletion, HTTP controls and restart persistence.
- `tests/interior-architect-ui-m35.cjs`: editor tools, local file allowlisting, guarded API, unchanged RMB walking, and keyboard shortcuts.
- All existing regression files remain in the isolated GitHub Actions test suite.
- M34 had six successful CI shards. M35 requires a new successful CI run before acceptance.

All code is original JavaScript for Demon Killer; no Godot dependency or RunUO source was imported.
