# M64 | NPC traffic, collision-checked navigation and gate queues

## Functional changes
- Existing cardinal BFS navigator now treats actually occupied NPC, living-player, monster and companion positions as obstacles in the route search; intangible ghosts do not block.
- A moving NPC can approach a target within one tile, but cannot overlap it. Alternative cardinal routes are attempted when a street is blocked.
- A portal step checks the other region's arrival tile and waits if another actor is standing there, preventing instant crowd stacking on gateways.
- Persistent `living.traffic` stores one movement record per NPC, with exact-once world-minute checks, movement counts, blocked attempts and throttled congestion events.
- Existing saved characters, world areas, business inventories and NPC positions are retained during migration.
- Read-only `GET /api/v1/traffic` and nine registered regression contracts.
- M61 guard patrols, M62 garrison supply journeys and M63 refugee migrations now use collision-aware route decisions.
- No new browser controls, HUD widgets, artwork, cutscene or audio updates.

## Verification
Isolated V8 simulations confirmed rerouting around a mobile, gate-entry waiting, successful portal release and idempotent traffic events. JavaScript syntax checks passed. The complete Node test suite and live browser/server testing remain outstanding. No RunUO GPL source copied.
