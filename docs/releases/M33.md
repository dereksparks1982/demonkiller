# Demon Killer M33 - Streaming Cell Hierarchy

**DK Server 2.13.0** | Single-player, engine-free JavaScript runtime.

## Why this build exists

The original Demon Killer v0.5.03 was titled *Streaming Spatial Bucket Index Foundation*. Its recovered manifest and archive notes also identify `DKStreamingMemoryManager.gd`, `DKSeamlessCellStreamingController.gd`, `DKCellRoot.gd`, `DKCellGeometry.gd`, `DKCellDoor.gd`, `DKRegionCellDurableState.gd` and reusable object shells. The recovered source files themselves are **not all accessible on the archive branch**. M33 independently reconstructs compatible design concepts, rather than claiming a line-for-line port or restoring Godot.

## Cell hierarchy

- Three **variable-size root cells** represent the existing 16×16 temple, 64×64 courtyard and 128×128 village. Area dimensions and approved 32px tiles are unchanged.
- Fifteen building footprints are defined as **child cells**. Their sizes follow the actual buildings, including the 16×16 temple exterior and 20×14 village bank. A building with `interior_ready:false` is **not** silently made enterable.
- Four existing door/gate connections form a graph between the playable root cells. Door and gate open states are read from existing `world.areas` objects; they are not duplicated in a rival streaming save.
- 16×16 **sectors** remain the lower-level tile and spatial-index divisions. Sectors are not rooms or whole streaming cells.

## Durable world state and server

- Adds `living.streaming_cells` with validated player-cell identity and per-cell visit count and timestamps. Entries persist in the existing atomic world save and survive server restarts.
- Server-side portal movement emits `cell.exit` and `cell.enter` events in addition to existing district events. Seamless movement within a root cell does not emit fake cell crossings.
- M32 and older world saves without cell records remain loadable. New records are added on startup; a stale cached cell pointer is repaired from the authoritative character location.
- Character deletion resets only that character's streaming visit history; geography, structures, NPCs, corpses and world ownership remain intact.
- Adds read-only `GET /api/v1/streaming-cells?radius=24` scoped to the current player region. The response contains the root cell, nearby nested cells at active/near LOD, and known playable links, not hidden distant areas.
- Sector-interest responses, map manifests, tile chunks and indexed fixtures carry a stable parent `streaming_cell_id` or `cell_id`.

## Client memory and rendering

- New `streaming-cell-shells-m33.js` stores reusable bounded object shells keyed by stable area and object identity. It references current authoritative area objects and does not copy or invent door state.
- The outdoor canvas now enumerates only camera-adjacent static objects through those shells, with an active/near priority; objects outside view remain in the server world.
- The browser fetches the nearby cell view opportunistically. If unavailable, the old renderer and terrain streaming still work.
- The approved hold-RMB continuous cardinal walking, C/P/I shortcuts and no-play-screen-buttons interface remain unchanged.

## Validation

- New `tests/streaming-cells-m33.cjs` checks hierarchy, varying dimensions, actual portals, saved visits, repeat crossings in one world minute, migration, player retirement, nearby visibility and HTTP restart.
- New `tests/streaming-cell-shells-m33.cjs` checks object-reference reuse, bounded pool eviction, context changes, script loading and movement preservation.
- Focused isolated execution confirmed three root cells, fifteen child building cells, four actual links, repeat visit conservation, and parent cell IDs in both sector and terrain metadata.
- **The complete `npm test --prefix server` run has not yet been confirmed as passing.** It must be run against a full checked-out repository before M33 is formally accepted.

## Next larger milestone
