# Demon Killer M32 - Streaming Outdoor Terrain

**DK Server 2.12.0**

## The world-sector system
- The established 16×16 tile sectors now serve the actual outdoor floor, walls and related tile-art layers, not just nearby NPC/entity lists.
- `GET /api/v1/sectors/manifest?area=...` supplies the current area's bounds and original static objects without shipping its whole terrain arrays.
- `GET /api/v1/sectors/chunk?area=...&sx=...&sy=...` continues to provide the seven ground/wall/decoration layers for an authorized 16×16 sector.
- Both endpoints restrict access to the player's current server region. They do not permit arbitrary remote world-map reads.

## Browser and local-server client
- On entering an outdoor region using a connected DK Server, the game loads the manifest and the immediately visible ring of sectors before displaying the area.
- Additional sectors prefetch ahead of movement, including sectors beyond the current 16-tile boundary. Requests share a bounded queue, and loaded chunks are cached without growing indefinitely.
- Evicted sectors release their tile data. The same sector can be streamed again when the player returns.
- Static building footprints, doors, gates and willow metadata remain intact. Sparse geometry is displayed as unavailable tiles until a sector arrives, never falsely presented as traversable grass.
- The browser-preview version continues using its established local maps. If server streaming fails at startup, it falls back to the original full-area endpoint.
- Three consecutive background terrain fetch failures trigger an **in-place recovery** to the full map. This keeps the character's current position and interpolation state rather than reloading the scene.
- All world movement and collision remain server-authoritative when connected. The approved smooth RMB walking and the C/P/I keyboard shortcuts are unchanged. No new gameplay buttons.

## Cache limits and tests
- Cached terrain is bounded to 28 sectors by default, with up to four simultaneous requests and deduplication of already loaded tiles.
- `tests/terrain-stream-m32.cjs` checks real village geometry, manifest minimization, chunk data, initial prefetch, eviction, concurrency, malformed packets, remote access and failure behavior.
- `tests/terrain-stream-ui-m32.cjs` checks script load order, existing walking, hotkeys, in-place recovery and local asset allowlisting.
- Focused isolated module checks and an actual village-map materialization check passed. The complete Node.js regression suite has **not** been confirmed as passing.
- The renderer still holds flat-sized tile-index arrays for efficient interaction with existing art and movement code. The large data arrays are populated on demand; future work can replace those indexes with fully sparse maps as the playable world grows.

## Source
All implementation is original JavaScript for Demon Killer's custom web runtime. No Godot dependency or RunUO code was added.
