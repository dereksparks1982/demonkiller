# M73 | Actual player and independent NPCs in the green world

**Date:** 2026-11-08  
**Game:** 0.2.71  
**DK Server:** 2.31.17  
**Working rule:** Development saves are disposable. Never reset automatically; use the explicit reset button.

## Goal

Move beyond the detached M72 walking surveyor by binding the actual saved character and a first population of independent NPCs to the *same hand-painted 9,216 × 9,216 world*. The owner rejected investing engineering time in preserving early temple/village saves while the replacement game is being built. The natural starting geography is still uniformly flat green grass. Do not generate a civilization or decorate it without the owner's instructions.

## Implemented

- `server/world-actors-m73.cjs`: optional `characters['1'].atlas_position={x,y,facing,steps}` uses the real player's slot-one identity, skills, inventory and entity registry. Entry and cardinal steps are checked against authoritative terrain, slope limits, boundaries and occupied positions. The original character's old `area_id` is retained temporarily because many legacy gameplay modules still require it.
- Development-only `new_character` actor transaction invokes the existing `createCharacter` pipeline and then explicitly starts the test character living in the new atlas, skipping the obsolete temple opening. This is a development shortcut, NOT a permanent lore/story change.
- The first atlas-native NPC system stores individually named guards, scouts, foragers and workers in `living.atlas_npcs`. No NPCs or towns are spawned automatically. The server validates IDs/roles/names/positions and prevents overlapping actors. Scouts/guards/foragers follow small deterministic local routes on the server's **world minute** via `living-world.advance`. Workers remain at the site until proper employment/construction stages exist.
- Fine `world-terrain-editor-m69.cjs` brush strokes and coarse `world-atlas-m70.cjs` cell fills now protect new characters and NPCs from impassable painting. M72's separate surveyor remains supported as a testing adapter.
- `GET /api/v1/world/actors` returns player state and a 25×25 radius neighborhood of real terrain plus nearby named NPC records. `POST /api/v1/world/actors` requires same-origin DK Server access and command-specific headers: `new_character`/`enter`, `step`, `introduce_npc` and `remove_npc`. Every accepted transaction uses the existing serialized durable writer. Reject unsupported parameters and malformed or overlapping entities.
- New UI `dk-world-explore-m73.html` displays original 32×32 human sprites on basic non-smoothed 2D pixel terrain. Create/enter a character, use WASD/arrows/right-mouse hold to move, left click to select a tile, place a named NPC of an assigned role or remove a selected one. Server saves all actions; browser polling only refreshes the picture.
- DK Architect's `WALK HERE` and Main Menu → Options → Persistent World → Enter the Living World use the M73 view, leaving the older M72 view present for regression compatibility.
- Main Menu Options now exposes a deliberate **RESET DEVELOPMENT WORLD** control that requires typing `RESET WORLD` and uses the existing revision-checked reset API. This is appropriate for a prototype that changes shape frequently; no old saved world is deleted as a side effect of installing this build.

## Verification

Isolated V8 checks using actual M67 grid, M69 terrain, M72 walking and M73 actors source passed for real-character global movement across Streaming Cell boundaries, NPC introduction, guard step, worker stationarity, collisions, invalid input rejection and leaving the previous world unchanged on failed requests.

`tests/world-actors-m73.cjs` adds nine Node regression scenarios including live HTTP writes, character creation through the existing pipeline, inventory/skill retention, saved state after restart, NPC persistence and an explicit development reset. The earlier M72 link assertion was updated to accept M73.

**Not verified in this environment:** the complete Node test suite, live Firefox interactions, long-running world tick, and integrated legacy temple-gameplay coexistence. This should be tested on the Linux checkout before calling gameplay finished.

## Current constraints

This is the first **character + atlas-NPC bridge**, not the final RunUO-equivalent persistent simulation. Atlas NPCs are not yet integrated with item serials, workplaces, supply chains, genuine construction projects, combat or factions. The original temple/courtyard/village runtime and associated `area_id` metadata remain temporarily because many legacy modules depend on them. The user has authorized a clean-reset development direction; prioritize removing these legacy dependencies in future builds rather than adding complex historical-save migrations.

The original M72 surveyor and M73 character should not be mistaken for two equal permanent player avatars. The M73 saved slot-one record is the forward direction; M72 is legacy test infrastructure.
