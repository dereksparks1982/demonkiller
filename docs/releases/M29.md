# Demon Killer M29 - Persistent Remains and Terrain Decay

DK Server 2.9.0. This release uses the existing authoritative world clock, entity serials, scheduler and world snapshot, with no change to movement, C/P/I shortcuts, or the 32-pixel art standard.

## World simulation
- Human NPCs and defeated imps now leave separate, persistent terrain-anchored remains.
- Each body progresses through fresh, early decay, advanced decay, skeletal and scattered stages according to saved world minutes.
- Human, demon and future beast remains have different lifetimes. Dry shelter delays decomposition, while the damp courtyard accelerates it. These are static environment conditions, not a live weather simulation.
- Bodies remain after the first loot action; coins and possessions can only be collected once. Skeletons can still contain loot until bones scatter. Demon loot piles remain separate from demon corpses.
- At the scattered stage, unclaimed physical possessions leave the world through the existing entity-registry cleanup. At final decomposition, a fading stain or ash mark becomes part of the saved ground layer.
- Preserved story remains are supported through a server-owned `preserved` flag; ordinary corpses and stains ultimately expire.
- Bounded corpse/terrain mark collections and inactive entity-reference pruning avoid indefinite growth.

## Game client
- Render all five corpse stages with intentionally simple 32px pixel shapes. Human and demon remains have distinct appearances.
- Render saved stains/ash beneath corpses and NPCs, with gradual fading, no collisions and no new play-screen buttons.
- Left-click inspects the stage. Double-click loots only a nearby body with recoverable possessions; the server validates distance and ownership.

## Save compatibility and tests
- Old M12 corpse data migrates on server startup without erasing loot or changing world identity. Legacy-format records remain valid during the initial load before migration is committed.
- `tests/terrain-remains-m29.cjs` covers decay schedule, environment, loot conservation, migration, monster deaths, permanent remains, expiry, stains, and HTTP restart.
- `tests/terrain-remains-ui-m29.cjs` protects rendering order and keyboard-only UI. Older M12 tests now expect bodies to persist after looting.
- Focused runtime checks passed for stages, human loot, demon corpse creation, legacy migration, item reconciliation, fading traces and expiration.
- Full `npm test --prefix server` execution still requires a local Node.js run or confirmed CI results. No unsupported claim of a complete suite pass.

## Scope
Single player. World time progresses while DK Server is running and performing scheduled catch-up. A stopped server does not simulate time. No external graphics, Godot runtime, or RunUO code was copied.
