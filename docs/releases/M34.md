# Demon Killer M34 | Streaming Cell Contents and Lifecycle

**DK Server 2.14.0.** Original engine-free server and browser code. No RunUO source or Godot code was imported.

## Architecture
- Streaming Cells remain **variable-sized** root regions and nested building footprints. The 16×16 tile **sectors** continue to serve terrain and proximity queries. Buildings without interiors stay exterior-only.
- The new server-side `cell-contents-m34.cjs` derives nearby fixture, mobile, monster, dropped-item, grave, corpse, and scavenger contents directly from the saved world. Object identities and player ownership are never duplicated in new cell saves.
- Contents are assigned to their active parent/root or building child cell. Fixtures follow true overlapping footprints, not only top-left tile positions.
- A new read-only local endpoint, `GET /api/v1/streaming-cells/contents`, provides a full initial snapshot followed by precise object/cell additions, updates, and removals. One-use cursors expire and are memory-capped; area changes and expired cursors cause a safe full refresh.
- Server requests are scoped to the current character's area, with radius limited to 8–32 tiles, hard caps of 512 visible entities and 32 nested child cells, and no remote area IDs accepted.
- Whole-world processing, mobile movement, NPC schedules, corpses and loot continue even when a cell's contents are unloaded by the browser. Existing world JSON and save recovery remain the sole authority.

## Browser integration
- `streaming-cell-contents-m34.js` applies contents deltas atomically to a bounded client cache and evicts objects that leave interest.
- Outdoor NPC, monster, corpse, grave and scavenger drawing uses materialized cell contents first. The M31 sector stream and previous world display remain as fallbacks if M34 contents cannot be fetched.
- Nearby door `open` and `locked` presentation states follow server fixture updates without copying unrelated object geometry or writing any client-side save state.
- No new gameplay buttons. Existing smooth right-mouse cardinal walking, C/P/I shortcuts, and the M32 terrain-chunk cache are unchanged.

## Verification
- `tests/cell-contents-m34.cjs`: nested cell ownership, no duplicate authority, bounded snapshots, precise changes, unloading, expiry, area changes, HTTP permissions and restart durability.
- `tests/cell-contents-ui-m34.cjs`: client delta application, atomic corruption rejection, door state, browser integration and movement regression.
- Full server regression suite continues to run through isolated, deadline-limited CI shards. M33 repair baseline had **six passing shards** before M34.
- **M34 acceptance depends on the complete latest GitHub CI run**, not just syntax checks.

## Intentional limits
Actual building interiors, large-map streaming without area-sized sparse arrays, and cell editor persistence are later milestones. This build does not invent interior rooms or pretend client-side unloading stops world simulation.
