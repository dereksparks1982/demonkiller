**Stage:** owner-requested build, no tag until acceptance.

## Courtyard cinematic

On the first courtyard visit from the temple, lock character input and hide the player. Pan the top-down camera ahead to Lilith, follow her north up the path, stop at the willow circle, and hold the camera for three visible prayer lines. Use the owner-approved twelve-panel transformation sheet:
\`assets/art/characters/crystal-woman/transformations/approved-willow-transformations-reference.png\`.

Six source panels per branch, no new sprite or hand-drawn substitute:
- Ghost/dead: red hair, green dress, golden healthy willow (top row).
- Living/resurrected: red hair, red dress, sickly black willow (bottom row).
After the last frame and a hold, pan back to the player and restore controls. The camera, prayer, stages, and return are one bounded timeline; completion is recorded only when finished.

## Save Management

Three separate controls, **only under Options**:
1. Delete Character: uses M26 character retirement; old world keeps advancing, no world reset.
2. Reset Server World: explicit type-to-confirm and the current authoritative revision. Serializes the world writer, builds a fresh seed, durably writes \`world.json\`, removes old checkpoints and event journal, creates a new verified checkpoint, clears in-memory interest trackers. The old character is necessarily removed with the world.
3. Start Fresh: same server reset when connected, plus browser character, scene progress, and Architect drafts. GitHub Pages cannot reset a server and only clears browser records.

A server reset is **not triggered by deployment**, only by confirmed user action. Loopback-only request, strict JSON shape, header \`X-DK-Control: reset-world\`, and revision check protect against accidental requests.

## Paper doll

Both \`test-center.html\` and \`outdoor.html\` use \`dk-paperdoll-m40.js\` and its right-side Classic UO-inspired command rail. **Delete Save buttons and their click handlers were removed from both paper dolls.** Available functions: Help, Options, Log Out, Journal, Skills, Status, Backpack, Profile. Guild, Quests and Peace/War remain visible but disabled rather than pretending to exist.

Reference for authentic buttons and behavior: Ultima Online's Classic Client paperdoll guide and ClassicUO PaperdollGump code. Independent implementation uses DK original assets and data, no external client code copied.
