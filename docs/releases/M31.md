# Demon Killer M31 - World Sectors and Nearby Streaming

**DK Server 2.11.0** - RunUO-inspired sector architecture, independently implemented in the custom DK runtime.

## Server world organization
- Existing 16×16-tile spatial sectors remain independent of room and region sizes. Temple: 1, courtyard: 16, village: 64 sectors.
- A new server-owned area-of-interest manager derives nearby sectors from the actual player location, including adjacent sectors before the player crosses their invisible boundaries.
- `GET /api/v1/sectors/interest` supplies an initial full visible-entity snapshot and then incremental upsert/remove changes through one-use, short-lived cursors. Only server-validated local entities are included.
- Cursor sessions are bounded and expire. A region transition, expired cursor, server restart or changed radius produces a safe full refresh.
- `GET /api/v1/sectors/chunk` delivers 16×16 tile chunks, including floor, walls, art layers and overlapping static objects, restricted to sectors near the player.
- The spatial index carries stable IDs and relevant visual fields for NPCs, monsters, graves, scavengers and corpses, not inventories or secret world state.
- NPC threat sensing uses sector activity tiers: every 5 world minutes nearby, every 15 for distant NPCs while a player is present. NPC movement, economics, hunger, territory changes, combat and the rest of the background world continue at their established rates.
- Both sector services are derived from the existing authoritative world snapshot. They never become a second save system.

## Game client
- Outdoor gameplay polls nearby sector changes and uses them for local NPC, monster, corpse, grave and scavenger rendering.
- Movement remains continuous. Crossing a sector boundary is not a room transition, teleport, loading screen or save reset.
- The older rendering path remains available if the local server is missing or a sector stream fails. Static GitHub Pages preview still works without DK Server.
- No additional play-screen buttons or changes to C, P, I and other approved controls.

## Future work
- The outdoor client still initially loads each whole map for terrain collision and drawing; the chunk endpoint prepares the future switch to streamed terrain without changing walking.
- Further server work should prioritize a unified world-interest graph for NPC interaction, map chunks, and optional multi-client networking without sacrificing single-player persistence.
