# Demon Killer World Server

This directory contains the Node.js 20+ authoritative world simulator for Demon Killer. It owns the single-player world save, terrain edits, NPC activity, persistence, and streaming data. No external npm dependencies are needed. New world-atlas terrain has a persistent default of **grass at elevation 0** for all 84,934,656 logical tiles. Only authored changes are stored, so no giant grass array is allocated. Painting a whole cell back to grass removes its cell override; per-tile elevation/material overrides remain independently editable.

To run from a source checkout: `node server/dk-server.cjs`. The default listener is **127.0.0.1:8766**. The game served by that process is the supported connected client. **GitHub Pages is a static browser preview and does not host this server.** Do not expose the loopback API to the public internet; remote hosting requires authentication and additional security.

The process saves to `server/data/world.json`, with verified checkpoints in the private save directory. Start/Stop controls pause and resume simulation. Closing the browser does not stop an already-running process, but shutting the server down freezes simulation rather than inventing offline progress.

Editing terrain through DK Architect sends an explicit, revision-checked command to the server; completed strokes save automatically. M70 offers a whole-world pixel painter at `/dk-world-architect-m70.html` or in the existing F8 Architect menu; it samples the 72×72 global Streaming Cell atlas, uses whole-cell material records for enormous ocean fills, and leaves detailed tile material/elevation overrides on top of those fills. No external graphics editor is required. Occupied or protected M68 prototype cells are skipped in large impassable paints, and the API reports which were skipped. Use **Logistics → Export Server Terrain** in the connected editor to export the sparse world terrain and heights as JSON. The read-only endpoints are `/api/v1/world/grid`, `/api/v1/world/terrain/sector?sx=0&sy=0`, `/api/v1/world/terrain/atlas?x=0&y=0&scale=128&columns=72&rows=72`, `/api/v1/world/terrain/coverage`, and `/api/v1/world/terrain/export`. The new cell-write endpoint is `POST /api/v1/architect/world-atlas`, with the `X-DK-Architect: world-atlas` header, JSON action `fill_cells` or `restore_cells`, and exact expected revision. Large fills are single validated server transactions; fine sculpting retains the M69 write endpoint. You may add `?cx=0&cy=0` to the export route for one Streaming Cell. **M70 paints unmaterialized world terrain throughout the full 9,216² atlas, but does not yet make every region walkable in gameplay.** Height-aware 2.5D rendering, physically connected rivers/coasts, water depths, underground cave editing, real building foundations, and autonomous city construction remain future implementation slices.

**M72 world walking:** The connected editor's **WALK HERE** button enters a simple top-down world-walking surveyor at a chosen global coordinate without loading old temple/village areas. `/dk-world-explore-m72.html` renders a bounded 25×25 tile viewport with the existing 32×32 human sprites. GET `/api/v1/world/walk` returns the persisted surveyor and ground/elevation tiles; POST `/api/v1/world/walk` performs a server-validated `place` (editor header `X-DK-World-Editor: place`) or single cardinal `step` (walking header `X-DK-World-Walk: step`). Sea, rivers, lakes, cliffs, boulders, crevasses and elevation jumps greater than one tile block movement. Unbuilt building blueprints do not block walking until real foundations exist. The global actor's position lives in the server world grid; movement does not materialize 84.9 million tiles. This is a **walkable terrain prototype**, not yet the final legacy-character/NPC/monster gameplay migration.

**M73 actual character and NPC atlas:** Open `/dk-world-explore-m73.html` from the main menu or the DK Architect WALK HERE button. A development character uses the genuine `characters['1']` record and its inventory, skills and persistent serial; creation through the new atlas development mode temporarily skips the retired temple opening. Existing characters can enter explicitly. NPCs introduced through this interface (scout, guard, forager or worker) live in the server-owned `living.atlas_npcs` registry, remain uniquely identified, and have deterministic nearby movement on the server's world clock (workers currently stay put). NPC placement is intentional, with no automatic towns or people. The new movement is connected to the same sparse global terrain and is blocked by impassable materials, excessive height differences and occupied tiles.

New routes: `GET /api/v1/world/actors` (nearby world characters and NPCs) and `POST /api/v1/world/actors`. Allowed actions are `new_character`, `enter`, `step`, `introduce_npc`, and `remove_npc`, with strict command validation and action-specific headers. The server serializes successful writes and saves before acknowledging them. Older temple-era services are still compiled, but **they are not the new atlas geography**; full job/commerce/quest migration is future work.

**Development reset:** The main menu's **RESET DEVELOPMENT WORLD** control calls the existing revision-checked `POST /api/v1/save/reset-world` only after the player types `RESET WORLD`. This intentionally discards current test terrain, characters, NPCs and progress and creates a clean grass seed. It never runs automatically. Treat saves as replaceable until the world model stabilizes; do not add elaborate compatibility layers just to protect temporary development saves.

Run the repository's Node regression suite with `npm --prefix server test`. Detailed development notes, release investigations, architecture, limitations, and the full former README have moved to [docs/](../docs/), including the [development handoff](../docs/development-handoff.md) and [server README archive](../docs/history/server-README-through-M68.md).

**M74 atlas resources:** Natural resource gathering is tied to actual saved atlas terrain. The new sparse `server/atlas-gathering-m74.cjs` registry stores harvested-node cooldown and physical player/NPC packs. `POST /api/v1/world/actors` action `gather`, header `X-DK-World-Work: gather`, enforces strict adjacency, carrying capacity and six-world-hour regrowth with durable saves. Foragers gather timber/herbs/reeds, stationed workers gather stone/clay once per world hour while the server runs, whether or not a browser is open. Default grass produces nothing. This is **not** construction, hauling, autonomous towns or trading. Full Node suite and connected browser verification are pending.

**M75 construction:** `server/atlas-construction-m75.cjs` saves exact global 2×2 shed and 3×3 cottage footprints, terrain/elevation preflight, site inventories, assigned workers, foundation/frame/roof work progress and completed collision. Supplies are physically debited from player/NPC M74 packs, then consumed per stage. Each assigned worker earns one gold per material delivered and one gold per work step, paid from `characters['1'].gold` into the NPC's persisted `coins`. No funds/materials means no work. The player may labor without paying themselves. Unfinished sites can be canceled with capacity-checked refunds of unused stock; completed structures cannot be casually canceled. Site terrain is protected against fine and broad paint. `POST /api/v1/world/construction`, header `X-DK-World-Work: construction`, requires a current `expected_revision`. Connected M73 atlas page includes site painting/placement and supplies controls. This first real construction pass does **not** include doors, interiors, rentals, contracts, hauling from remote regions or self-founded towns. Run `node --test tests/atlas-construction-m75.cjs` and `npm --prefix server test` in Linux checkout; browser acceptance remains necessary.
